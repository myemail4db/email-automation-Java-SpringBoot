Current Status

Completed Core workflow

  • Spring Boot backend, Gmail OAuth 2.0, and Gmail API connectivity
  • Label-based Gmail retrieval and label movement
  • Email extraction, DTO processing, filtering, and normalization
  • TXT and DOCX export for manual review
  • Manual review checkpoint before sending
  • ZIP creation and outbound Gmail delivery
  • Workflow reporting for export, send, archive, duplicate, and partial-success outcomes

Completed Send safety and duplicate prevention

  • Gmail message ID persisted in filenames as _GMAIL-<messageId>
  • Previously sent messages detected by Gmail message ID before ZIP creation
  • Duplicate files moved to duplicate/ and excluded from delivery
  • Duplicate filename collisions preserved with _2, _3, and later suffixes
  • Successfully sent individual files archived in sent_archive_email/
  • The exact successfully sent ZIP archived in sent_archive_zip/
  • Temporary ZIP removed when Gmail delivery fails
  • JUnit 5 / Mockito coverage for duplicate and ZIP lifecycle safety paths
  • Real Gmail runtime validation completed for successful send, duplicate rejection, and repeated duplicate collisions

Current Version 1 flow

Export → Manual Review → Send → Sent Archives

Exported files wait in processed_review/. The user reviews and may modify them before continuing. During Send, previously sent Gmail IDs are moved to duplicate/. New files are ZIPped and sent. After confirmed delivery, the individual files move to sent_archive_email/ and the exact ZIP moves to sent_archive_zip/.

Next Command-line interface

The next development step is a command-line interface that calls the same EmailExportService and EmailSendService used by the web/API layer. This adds command-line operation without duplicating the business logic.

Planned later

Security hardening, protected credential storage, encrypted ZIP delivery, expanded monitoring, a possible React review experience, and additional email provider integrations remain future enhancements.
