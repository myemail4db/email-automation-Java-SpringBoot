System design

Architecture

Email Automation is a Java 17 Spring Boot application with two explicit workflow entry points: Export and Send. The user-facing controllers stay thin while service classes own Gmail access, extraction, filtering, file generation, duplicate detection, ZIP lifecycle, delivery, and archiving.

Export path

ExportController
      ↓
EmailExportService
  ├── GmailService ── GmailAuthService ── Gmail API
  ├── EmailBodyExtractorService
  ├── TextFilterService
  └── FileExportService ── TXT / DOCX
      ↓
processed_review/
      ↓
USER MANUAL REVIEW

Send path

SendController
      ↓
EmailSendService
  ├── ArchiveService ── duplicate detection by Gmail message ID
  ├── ZipExportService ── create / delete / archive ZIP
  └── GmailService ── Gmail API send
      ↓
Successful send
  ├── reviewed files → sent_archive_email/
  └── exact ZIP      → sent_archive_zip/

Responsibility boundaries

ComponentResponsibility
GmailAuthServiceOAuth authorization, token storage, and authenticated Gmail client.
GmailServiceRetrieve Gmail messages, update Gmail labels, and send the completed ZIP.
EmailBodyExtractorServiceExtract Gmail content and preserve the Gmail message ID.
TextFilterServiceClean and normalize message content.
FileExportServiceCreate TXT/DOCX review files with _GMAIL-<messageId> identity in filenames.
ArchiveServiceDetect previously sent Gmail IDs, move duplicates to duplicate/, and archive successfully sent individual files.
ZipExportServiceCreate temporary ZIPs, remove failed-send ZIPs, and archive successfully sent ZIPs.
EmailExportServiceCoordinate Export and return a WorkflowReport.
EmailSendServiceCoordinate duplicate check → ZIP → Gmail send → individual archive → ZIP archive and report partial-success states.

Why the manual checkpoint matters

Export intentionally stops after writing review files. The application does not automatically send them. The user opens, reviews, edits if necessary, and saves the files before explicitly starting Send.
