Implementation choices

Engineering Decisions

Service separation

External API access, content processing, file handling, archiving, and delivery are separated instead of being embedded in controllers. Controllers remain focused on HTTP interaction while services perform the work.

Defensive processing

The workflow checks common failure conditions including missing export formats, null service results, empty email collections, invalid content, and failed file saves. The goal is a meaningful workflow result instead of an uncontrolled failure.

Duplicate filenames

Generated files use readable job-oriented names. When a filename already exists, the export logic adds a numeric suffix rather than overwriting the existing file.

Resource handling

File and ZIP operations use scoped resource management so streams are closed reliably even when processing fails.

Testing strategy

JUnit 5 and Mockito are used for representative automated testing. Current tests cover Spring context loading, dependency mocking, defensive behavior, and successful workflow behavior. Planned coverage targets important boundaries such as Gmail retrieval, filtering, file processing, ZIP creation, outbound delivery, and orchestration.

Security posture

OAuth credentials, access tokens, refresh tokens, and other sensitive configuration should not be committed to source control. Logging should provide useful operational detail without exposing Gmail or OAuth secrets. Additional credential protection, archive protection, integrity checks, and recovery controls are roadmap items.
